# Copilot Interaction Rules

## Information vs Action Requests

**CRITICAL RULE**: When the user asks for information, explanation, or analysis - DO NOT make code changes.

Examples of information requests (DO NOT edit code):
- "Can you explain why..."
- "Walk me through the logic..."
- "Why does X produce Y?"
- "What is happening here?"
- "Help me understand..."

Only make code changes when the user explicitly requests an action:
- "Fix this..."
- "Change X to Y..."
- "Update the code to..."
- "Implement..."
- "Let's try..."

## Rationale

Past attempts to solve problems have sometimes failed or made things worse. The user needs to understand the problem fully before deciding on a solution. Making changes without explicit approval can:
1. Mask the real problem
2. Create new issues
3. Make debugging harder
4. Waste time on approaches the user has already considered

## Process

1. When asked for information → Explain, analyze, trace through code
2. Wait for user to decide on approach
3. Only implement changes when explicitly requested
